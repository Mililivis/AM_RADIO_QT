# AM радіо на RTL-SDR (Qt6)

AM-приймач з GUI для Raspberry Pi 5 + RTL-SDR Blog V4: сканування ефіру, список знайдених станцій,
прослуховування. Працює через SSH: вікно — X11-прокидання, звук — потік PCM по тому ж SSH.

Драйвер SDR (C++ обгортка над librtlsdr) лежить у папці [`SDR/`](SDR/README.md).

## Встановлення з нуля (на Пі)

```bash
git clone https://github.com/Mililivis/AM_RADIO_QT.git ~/AM_RADIO_QT
cd ~/AM_RADIO_QT
./SDR/scripts/install_librtlsdr.sh            # librtlsdr з підтримкою V4 (rtl-sdr-blog), один раз
sudo apt install -y qt6-base-dev libpulse-dev
cmake -B build && cmake --build build -j4
```

## Команди (на ноутбуці)

Зібрати / оновити на Пі (копіює `~/AM_RADIO_QT` на Пі і збирає):

```bash
~/AM_RADIO_QT/scripts/deploy.sh
```

Запустити радіо (вікно і звук на ноутбуці):

```bash
~/AM_RADIO_QT/scripts/run_remote.sh
```

Те саме вручну, однією командою:

```bash
ssh -Y -C mililivis@10.42.0.221 'cd ~/AM_RADIO_QT && QT_QPA_PLATFORM=xcb exec ./build/am_radio --audio-stdout' | pw-cat --playback --format s16 --rate 48000 --channels 1 --latency 100ms -
```

- `-Y` — X11-прокидання (вікно Qt малюється на ноутбуці), `-C` — стиснення трафіку.
- `--audio-stdout` — програма пише звук (s16le, моно, 48 кГц) у stdout, SSH передає його, `pw-cat` програє.
  Замість `pw-cat` можна `aplay -f S16_LE -r 48000 -c 1`.
- Без `--audio-stdout` звук іде в PulseAudio/PipeWire самої Пі (динамік/навушники на Пі).
- `--tune 9615` — одразу почати слухати частоту (кГц), `--device 1` — інший донгл.

Інший адрес Пі: `PI=user@host ~/AM_RADIO_QT/scripts/run_remote.sh`.

## Користування

1. **Діапазон** — СХ, ДХ або один із КХ-діапазонів (49 м, 41 м, 31 м...), або «Довільний» з власними межами.
   **Крок** — сітка каналів (9 кГц для ДХ/СХ, 5 кГц для КХ). **Поріг** — на скільки дБ несуча має бути
   вище шуму, змінюється і після сканування (список оновлюється одразу).
2. **Сканувати** — за ~0.5–1 с будує спектр діапазону і знаходить несучі на сітці каналів.
3. Подвійний клік по станції в таблиці або клік по спектру — слухати. ◀ ▶ — попередня / наступна станція.
4. **Смуга** — ширина фільтра (вужче — менше завад від сусідів, але глухіший звук).
   **Підсилення** — для слабкої антени більше, якщо станції «злипаються» або сильний фон — менше.

Нижній спектр показує ±72 кГц навколо станції, червоним — смуга фільтра.
Налаштування і список останніх знайдених станцій зберігаються (`~/.config/AM_RADIO_QT/am_radio.conf` на Пі).

## Будова

```
SDR/                  драйвер RTL-SDR + утиліта sdr_test
src/Dsp.*             FFT, FIR-фільтри, NCO, AM-демодулятор (1.152 MS/s -> 144 k -> 48 k, детектор огинаючої + АРП)
src/Scanner.*         сканування: вікна 2.048 MS/s з перекриттям, усереднений спектр, пошук несучих
src/AudioOutput.*     звук: PulseAudio або stdout, буфер від джитера
src/RadioEngine.*     володіє SDR: сканування (окремий потік) / прийом (потік librtlsdr)
src/SpectrumWidget.*  графік спектра
src/MainWindow.*      GUI
```

SDR налаштовується на 200 кГц вище станції, щоб DC-пік RTL2832 не потрапляв у канал.
DSP займає ~5% одного ядра Pi 5.

## Проблеми

| Симптом | Що робити |
|---|---|
| `cannot connect to X server` | підключатися з `-Y`; на Пі в `/etc/ssh/sshd_config` має бути `X11Forwarding yes` |
| Вікно є, звуку немає | у рядку стану має бути «Звук: stdout». Перевірте, що `pw-cat` запущений на ноутбуці (див. команду) |
| Звук переривається | слабка мережа: збільшити `--latency 300ms` у `pw-cat` |
| Станцій не знайдено | перевірити антену, збільшити підсилення, зменшити поріг. СХ краще чути ввечері/вночі |
| `Failed to open RTL-SDR ... busy` | донгл зайнятий іншою програмою (rtl_test, sdr_test, rtl_tcp) |
